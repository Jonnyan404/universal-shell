# 主界面布局：选定方案与落地约束

> 决策：**B（表格）+ D（检查器）合并为程序主界面；A（分组卡片）用于模板库；移动端沿用「列表 + 全屏二级页」壳，不新增第三套逻辑。**
> 可交互原型：[`06-merged-bd.html`](06-merged-bd.html)（顶部可切「桌面 / 手机」，右上可切 24 / 48 / 120 规模）

---

## 1. 为什么这不是三选一

B 和 D 描述的是**同一屏的两个区域**，不是两种界面：

- B 是「列表区长什么样」——表格、可排序、可连选；
- D 是「选中之后在哪看」——检查器，五个 Tab，不离开列表。

把它们拼起来只有一处需要决策：**检查器是常驻右栏，还是抽屉**。原型里做的是常驻 376px 右栏 + 可一键收起（`检查器` 按钮），因为它让「扫列表 → 看详情 → 继续扫」不需要任何跳转；屏幕窄于 1280px 时自动降级为抽屉。

A 用在模板库是另一回事：模板的使用动作是「浏览 → 识别 → 导入一次」，不是「持续管理」。卡片能承载图标、分类、一句话说明和「导入」主按钮，识别效率高于表格；而模板库不需要批量启停、不需要看运行时长，表格的列对齐优势在这里用不上。

**一句话：程序是「要长期运维的对象」，模板是「一次性挑选的商品」。前者用表格 + 检查器，后者用卡片。**

## 2. 区域映射

| 区域 | 视图 | 关键交互 | 对应原型 |
|---|---|---|---|
| 程序主界面 · 列表 | 高密度表格（双档行高） | 列排序、Shift 连选、`↑↓` 切换、`/` 聚焦搜索 | B |
| 程序主界面 · 详情 | 常驻检查器（概览/配置/调度/日志/更新） | 行选中即刷新；`Enter` 聚焦；`Esc` 收起 | D |
| 模板库 | 分组卡片（分类分组 + 折叠） | 分类树、搜索、单卡「导入」 | A |
| 日志中心 / 设置 | 维持现状 | — | 现有 |
| 移动端 · 列表 | 两行式列表 + 分类小标题 | 点行进详情；顶部「选择」进批量态 | 06 的手机档 |
| 移动端 · 详情 | 全屏二级页 | 返回即回列表；底部动作区 | 06 的手机档 |

## 3. 断点与降级（这是"兼容移动端"的全部内容）

| 宽度 | 列表 | 详情 | 导航 |
|---|---|---|---|
| ≥ 1280px | 表格，全部列 | 常驻右栏 376px | 图标窄栏 50px |
| 960–1279px | 表格，隐藏「分类 / 运行」列 | 抽屉（点行滑出，覆盖右侧 420px） | 图标窄栏 |
| 720–959px | 表格降为三列：状态 / 名称 / 版本 | 全屏页 | 图标窄栏 |
| < 720px | 两行列表 + 分类小标题 | 全屏页（带返回栏） | 底部 Tab 四栏 |

降级原则（避免维护两套逻辑）：

1. **只有呈现变，数据与动作不变**：`workspace_list` 一份数据，`start/stop/restart/open/log/edit` 一套动作函数，桌面和手机都调它。
2. **表格不重写成卡片**：窄屏下表格退化为"行内两行文本"，仍是同一个渲染函数，只是 CSS 隐藏次要列。
3. **详情只有一种内容结构**：五个区块（概览/配置/调度/日志/更新）在桌面是 Tab，在手机是纵向堆叠——同一份 HTML 片段，换容器而已。
4. **批量在手机上换入口，不换实现**：顶部「选择」只是把勾选框显出来，底部操作条复用桌面那组 `data-act`。

## 4. 明确不做的事

- **不做看板（C）**：它和表格的状态列信息重复，却要多维护一套拖拽 + 状态机约束；120 个程序时横向滚动成本高于收益。
- **不做健康矩阵（E）作为主界面**：一屏看全局确实爽，但它不能改配置，最终还是要跳回列表；等主界面稳定后，可以作为「总览」Tab 增量加，不影响现有结构。
- **不给三种视图都做全功能**：视图切换器一旦存在，用户会期待每个视图都能完成所有操作，维护成本翻倍。**只保留表格一种列表形态**，密度用「紧凑/标准」两档解决。
- **不在移动端做表格**：手机上表格的横向滚动是反模式，直接降级为两行列表。

## 5. 实施拆解（按此顺序，每步可独立验收）

| 步 | 改动 | 文件 | 验收 |
|---|---|---|---|
| 1 | 列表区改为表格：表头排序、双档行高、行选中态 | `frontend/workbench.js`（`renderList`）、`styles.css` | 48 个程序下能排序、能选中，列表区不再挤在 200px 侧栏 |
| 2 | 侧栏改为图标窄栏 + 分类筛选 chips | `frontend/index.html`、`styles.css` | 主区宽度增加 ≥ 200px，分类可筛 |
| 3 | 检查器：把现有 `manage-view` 的五个区块搬进右栏 Tab | `frontend/index.html`、`main.js`、`workbench.js` | 选中行后右侧出详情，启停/日志/编辑均可用 |
| 4 | 批量条：勾选后就地出现，Shift 连选 | `workbench.js` | 选 20 个批量停止，列表不跳动 |
| 5 | 模板库改分组卡片（分类分组 + 折叠 + 计数） | `main.js`（`renderLibrary`）、`styles.css` | 分类可折叠，导入仍走原流程 |
| 6 | 移动端：把现有卡片流改为两行列表 + 详情全屏页 | `main.js`、`styles.css`（`@media max-width:720px`） | 手机上点行进详情、返回回列表、批量可用 |

> 现有 `workbench.js` 已有 `st.items / checked / filter / query` 这套状态，第 1、4 步是**改造**而不是重写；`manage-view` 的五个区块已有 DOM，第 3 步是**搬移 + 加 Tab 壳**。

## 6. 需要你拍板的两点

1. **检查器默认常驻还是默认收起？** 常驻更适合"边扫边看"，但会吃掉 376px；如果主屏常在 1280 以下，建议默认收起、点行自动展开（原型已实现这个行为）。
2. **移动端是否保留"卡片"作为可选视图？** 现有阶段 G 的卡片流已经能用；我的建议是**只保留两行列表**（信息密度更高、和桌面表格同源），卡片视图下线，减少一套样式。
